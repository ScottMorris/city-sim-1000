# Documentation Truth Sweep

**Status:** cleanup batch. Each item below is a place where a doc, comment, or UI string asserts something the code demonstrably doesn't do (or vice versa). None changes behaviour on its own; together they are the drift that lets real regressions hide. Items that *do* need behaviour decisions have their own feature docs — this sweep is everything that only needs the words fixed or a small dead branch removed.

## Items

1. **`docs/tile-model.md` "exactly one exception"** (§compat pairs and §open questions): the code carries **two** compat exceptions — `COMPAT_EXCEPTIONS` in `crates/city-sim-core/src/occupants.rs:975-995` adds `Structure + PowerLine`, and its own comment explains the doc counted same-stratum pairs only. Update both doc sites.
2. **`docs/tile-model.md` on `Trees + PowerLine`** claims the pair "conflicts by default — physically correct, and again no rule", but `Tool::Tree` deliberately plants through a live line, producing a set `validate_set` rejects — pinned as `known_defect_trees_are_planted_through_a_live_hydro_line` (`occupants.rs:2356`) and worked around in the renderer. Meanwhile `manual.html` promises the line survives tree-planting, which is what actually happens. Resolve the three-way contradiction in favour of the manual (code already follows it): make the pair a legal compat exception (or move trees off the overhead-conflict path), delete the known-defect pin, and fix the model doc.
3. **`docs/wasm-sim-audit.md` is partly inverted** and reads as current (update headers stop at 2026-07-22): item A1 ("power line destroys zones") has been false since #177 — `commands.rs:243-265` leaves the surface stratum untouched; item A2 frames the bulldoze precedence as a TS/Rust deviation, but the oracle was rewritten to match Rust, leaving only the design gap now tracked in `layer-scoped-bulldozer.md`. Mark both resolved with pointers, and re-point still-open items (A3→`water-source-gating.md`, A5→`population-decline.md`, A6→`lighting-bylaws.md`, A7→`happiness-and-abandonment.md`, B2/B5→`sim-feedback-channel.md`) so the audit becomes an index instead of a second source of truth.
4. **`SPEC.md` "Water Pipe: Requires Underground View"**: no such gate exists (`Tool::WaterPipe` has no guard; the auto-switch in `main.ts` merely makes it usually true). Reword to describe the tool-implies-stratum behaviour once `view-layers.md` lands, or soften now.
5. **`SPEC.md` "Building centre markers are tinted by power status"**: the renderer draws no marker for `Active` buildings at all — only no-power/no-water icons on inactive ones (`renderer.ts:565-625`). The SPEC's own next sentence anticipated the change; delete the stale first half.
6. **`docs/manual.md` pipe cost**: says $5/tile; actual cost is 4 (`commands.rs:39`, `constants.ts:76`). Same file still calls water-source proximity a "planned feature", which matches the code today but will be superseded by `water-source-gating.md` — cross-reference rather than duplicate.
7. **`app/src/ui/hud.ts:186-187` "Coming soon: pipes and underground view."**: dead branch — `ToolDetails.unavailable` (`toolInfo.ts:19`) is never assigned, and the feature it disclaims has shipped. Remove (or repurpose as the stratum indicator per `view-layers.md`).
8. **`crates/city-sim-core/src/occupants.rs:1329-1332`** claims underground occupants are "only reachable from the underground view" — the invariant the engine assumes but cannot enforce until `layer-scoped-bulldozer.md` ships. Reword to reference the stratum-scoped command once it exists (also listed in that doc's touch list).
9. **`app/src/game/clientState.ts:42-44` sanitiser allow-list** is missing `'wilderness'`, silently resetting that minimap mode on save load — the one behavioural fix in this sweep, small enough to ride along (also noted in `view-layers.md`, which later restructures the enum).
10. **Legacy-save structure billing — verify, then document**: the old game billed maintenance and counted water output for a `kind=WaterPump/Park` tile with no `BuildingInstance` (a pre-migration save artifact); the stack deleted that path as "structurally unreachable". True for live play — but add one test that `import_legacy` either synthesizes a `BuildingInstance` for such a tile or documents that its upkeep/output vanishes. If the test finds real saves lose function, that graduates to its own fix.

## Ground rule going forward

`AGENTS.md`/`CLAUDE.md` already require updating `README.md`, `docs/game-parameters.md`, `manual.html`, and `SPEC.md` alongside any behaviour change they describe, in the same commit. Most items above predate or slipped past that rule; the sweep is the backlog payment. The audit-as-index change (item 3) is what keeps it paid down: one live tracker per gap, docs point at it.
