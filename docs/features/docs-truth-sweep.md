# Documentation Truth Sweep

**Status:** cleanup batch. Each item below is a place where a doc, comment, or UI string asserts something the code demonstrably doesn't do (or vice versa). None changes behaviour on its own; together they are the drift that lets real regressions hide. Items that *do* need behaviour decisions have their own feature docs — this sweep is everything that only needs the words fixed or a small dead branch removed.

## Items

1. ~~**`docs/tile-model.md` "exactly one exception"**~~ **Fixed.** The §compat-pairs total now reads "19 same-stratum pairs, exactly one same-stratum exception", with a follow-on sentence naming `COMPAT_EXCEPTIONS`'s second, cross-stratum entry (`Structure` + `PowerLine`, `crates/city-sim-core/src/occupants.rs`).
2. **`docs/tile-model.md` on `Trees + PowerLine`** claims the pair "conflicts by default — physically correct, and again no rule", but `Tool::Tree` deliberately plants through a live line, producing a set `validate_set` rejects — pinned as `known_defect_trees_are_planted_through_a_live_hydro_line` (`occupants.rs:2356`) and worked around in the renderer. Meanwhile `manual.html` promises the line survives tree-planting, which is what actually happens. Resolve the three-way contradiction in favour of the manual (code already follows it): make the pair a legal compat exception (or move trees off the overhead-conflict path), delete the known-defect pin, and fix the model doc.
3. ~~**`docs/wasm-sim-audit.md` was partly inverted**~~ **Fixed, and kept current.** A1/A2/A3/A4/A7/A9 (and several B/D items) are now struck through in a **Resolved** checklist per section with pointers to what closed them; A6 (lighting bylaws) joined them once `Policies::lighting` shipped — see `lighting-bylaws.md`. Still-open items point at their feature doc inline (A5→`population-decline.md`, A7 is resolved, B2/B5→`sim-feedback-channel.md`); the audit is an index now, not a second source of truth. Re-verify the "Reconciled" date at the top stays current the next time behaviour under it changes.
4. ~~**`SPEC.md` "Water Pipe: Requires Underground View"**~~ **Fixed.** The bullet now describes the tool-implies-stratum behaviour (selecting the tool auto-switches the client's `View`) plus the real engine-side gate `#198` added: `Tool::WaterPipe` refuses a command whose `stratum` isn't `Underground`.

10. ~~**Legacy-save structure billing — verify, then document**~~ **Verified, doesn't graduate.** `import::tests::a_structure_tile_with_no_building_id_imports_as_bare_ground_with_no_upkeep_or_output` (`crates/city-sim-core/src/import.rs`) pins the answer: `tile_from_v4`'s existing "a ghost structure drops its tag" rule (`is_structure_kind(kind) && building_id.is_some()`) already decides this case, so a `kind = WaterPump`/`Park` tile with no `building_id` imports as bare, unbilled ground — no `BuildingInstance` is synthesized, `water_output`/`power_plant_mw` stay zero. The old TS engine's billing for such a tile doesn't survive the import, but nothing `import_legacy` can produce today writes a structure kind with no id in the first place, so no real save loses function — it does not graduate to its own fix.

## Ground rule going forward

`AGENTS.md`/`CLAUDE.md` already require updating `README.md`, `docs/game-parameters.md`, `manual.html`, and `SPEC.md` alongside any behaviour change they describe, in the same commit. Most items above predate or slipped past that rule; the sweep is the backlog payment. The audit-as-index change (item 3) is what keeps it paid down: one live tracker per gap, docs point at it.
